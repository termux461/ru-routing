# Источники и отбор

## Каталог сервисов

Фактические доменные имена и номера ASN сверены 29 октября 2026 с репозиторием
[kozlovartem20201/amnezia-vpn-russia](https://github.com/kozlovartem20201/amnezia-vpn-russia),
снимок [2f3f998d7403e16e903f721748a16a244a7cff38](https://github.com/kozlovartem20201/amnezia-vpn-russia/tree/2f3f998d7403e16e903f721748a16a244a7cff38/sources).

Использованы фактические данные из `sources/domains.txt`, `sources/asn.txt`,
`sources/protection-asn.txt`. Python-код, готовые результаты сборки и текст README
исходного проекта не переносились. PHP-реализация и тесты самостоятельные.
Упоминание источника не означает, что сторонний репозиторий распространяется по MIT.

Каталог объединён с первоначальным списком этого проекта, дубликаты удалены,
кириллические домены приведены к punycode. Сохранены отдельные домены для входа,
API, закупочных площадок и статики. Изначально включены 826 уникальных доменов в 11 категориях; позднее каталог пополняется автоматически.
Каталог не является исчерпывающим реестром российских сайтов и не проверяет
блокировки каждого сайта в РФ. Устаревшие и неразрешаемые адреса отражаются в отчёте.

## Подсети

- [IPdeny RU aggregated](https://www.ipdeny.com/ipblocks/data/aggregated/ru-aggregated.zone):
  база регистрации IPv4 для допуска доменных адресов и ограничения сетей сервисов.
- [RIPEstat announced-prefixes](https://stat.ripe.net/docs/data-api/api-endpoints/announced-prefixes):
  актуальные BGP-анонсы явно перечисленных ASN. BGP-анонс сам по себе не доказывает
  исключительное использование сети одним сервисом или физическое размещение в РФ.
- Из первоначального набора ASN исключены Yandex.Cloud AS200350 и
  Сбербанк-Телеком AS206673: общие облачные/телеком-сети не добавляются целиком.
- Подсети из `asn.txt` пересекаются с IPdeny RU математически точно: если российской
  является только часть анонса, остальная часть не исключается из VPN.
- `protection-asn.txt` служит только для допуска отдельных DNS-адресов выбранных
  сервисов. Ни одна полная подсеть такого ASN не экспортируется автоматически.

Названия компаний в комментариях — ориентир для ручной проверки, не результат
автоматической проверки собственности. Перед добавлением ASN проверяйте его
текущее назначение на RIPEstat. Изменение владельца ASN может изменить охват правил.

## DNS и обновления

Основной DNS-over-HTTPS: `dns.google/resolve`; резервные при ошибках или пустом ответе: `cloudflare-dns.com/dns-query` и `dns.adguard-dns.com/dns-query`. Для каждого домена запрашивается запись A, а также
вариант `www`. Эти ответы объединяются без расширения отдельных адресов до /24.
IPv6 в файлы не включается. Параллелизм ограничен 12 запросами.

IPdeny, RIPEstat и DNS запрашиваются заново при каждой сборке. Ежечасно новые домены из указанного проекта-источника сверяются с текущим каталогом; при наличии российского IPv4 и отсутствии ошибок DNS они автоматически добавляются в свою категорию `sources/domains.txt`. Это не проверяет принадлежность сайта или его доступность из РФ. В `dist/report.json` сохраняются время сборки, SHA-256 каталога,
статистика по ASN, пропуски доменов, отфильтрованные адреса и ошибки DNS.

## Границы проверки

Тесты проверяют формат, фильтрацию, границы CIDR, пересечение сетей, разделение полных
и точечных ASN, обработку DNS и отсутствие резкого сокращения каталога. Сборка с
реальными источниками проверяет получение данных. Это не проверка доступности
каждого сайта из России и не испытание импорта на всех версиях VPN-клиентов.


## Дополнительные источники и очередь

Тематические каталоги `category-bank-ru`, `category-gov-ru`, `category-medicine-ru`, `category-education-ru`, `category-ecommerce-ru`, `category-retail-ru`, `category-travel-ru` и `category-tech-media-ru` проекта [v2fly/domain-list-community](https://github.com/v2fly/domain-list-community) используются как дополнительные источники кандидатов; проект распространяется под MIT, текст приведён в `THIRD_PARTY_V2FLY_LICENSE.txt`. Принимаются только конкретные доменные записи, без include, regexp, атрибутов и общих TLD.

Также проверяются типовые поддомены под заранее заданными основными сервисами. Совпадение DNS и RU IP не является проверкой собственности и доступности сайта. Очередь хранит последний проверенный домен в `dist/discovery.json`; очередная порция идёт за ним в алфавитном порядке и зацикливается. Поиск доступен для любой конкретной русской организации только если она присутствует в одном из исходных списков или в явно заданном наборе.

Резервные резолверы Cloudflare и AdGuard используют стандартный бинарный DNS-over-HTTPS. Российские AS8901 (ГКУ «Мосгортелеком») и AS62268 (АО «Электронная Москва») добавлены для допуска только адресов выбранных доменов; подсети целиком не добавляются. Данные о владельцах проверялись по RIPEstat на момент изменения.
