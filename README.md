# RU Routing: выбранные сервисы через VPN

Готовый список для раздельного туннелирования: **только выбранные сервисы идут через VPN, остальные — напрямую**, если в VPN-клиенте выбран соответствующий режим. Поддерживаются Telegram, YouTube, Instagram / Facebook, Discord, X, ChatGPT / OpenAI и TikTok. Выбор отдельных сервисов: [страница проекта](https://termux461.github.io/ru-routing/).

## Amnezia VPN

1. Скачайте [vpn-list.json](dist/vpn-list.json) — это список всех поддерживаемых сервисов. Для отдельных сервисов выберите их на [странице](https://termux461.github.io/ru-routing/) и скачайте Amnezia JSON.
2. Отключите VPN. Откройте **Настройки → Соединение → Раздельное туннелирование сайтов**.
3. Выберите **«Сайты из списка должны открываться через VPN»**. Важно: у противоположного режима другой список.
4. Выберите **Импорт → Заменить список** и укажите JSON. Замена удалит прежние пользовательские записи этого режима; сохраните их заранее, если нужны.
5. Подключите VPN и проверьте Telegram и другие выбранные сервисы. Откройте российский сервис и проверьте, что он видит IP вашего провайдера.

Настройки зависят от версии Amnezia, платформы и профиля VPN. Если клиент сообщает, что профиль не поддерживает раздельное туннелирование, настройте совместимый профиль у администратора VPN. Банковские приложения, определяющие сам факт работы VPN, могут требовать настройки раздельного туннелирования приложений.

## Telegram и ограничения

Список включает официальные **IPv4-подсети Telegram** из [core.telegram.org/resources/cidr.txt](https://core.telegram.org/resources/cidr.txt) и обнаруженные IPv4 отдельных доменов. IPv6 из источника не импортируется: поведение IPv6 определяется клиентом и его настройками и этим файлом не гарантируется.

Для YouTube и остальных сервисов используются IP доменов из `sources/vpn-services.json`, найденные во время сборки. У CDN адреса часто меняются и зависят от региона, а разные домены могут делить один IP. Поэтому адреса, которые не попали в DNS-ответ во время сборки, могут продолжить идти напрямую; один выбранный IP также может направить через VPN посторонние сайты. Файл не гарантирует работу всех видеопотоков, приложений, голосовых звонков и IPv6. Если Telegram не работает даже без раздельного туннелирования, проверьте работоспособность VPN-сервера и подключение отдельно.

## Файлы

| Файл | Назначение |
| --- | --- |
| `dist/vpn-list.json` | Amnezia: все выбранные сервисы через VPN |
| `dist/vpn-catalog.json` | Каталог и группы для страницы |
| `dist/vpn-sing-box.json` | Source rule-set v3 для sing-box |
| `dist/vpn-clash.yaml` | Classical rule-provider для Clash / Mihomo |
| `dist/vpn-ipv4.txt` | IPv4 и CIDR для клиентов, которые принимают текстовый список |
| `dist/vpn-report.json` | Время, количество адресов Telegram и домены без IPv4 |

Для sing-box настройте правило `rule_set` на ваш VPN outbound и убедитесь, что маршрут по умолчанию ведёт в `direct`. Для Clash/Mihomo примените `RULE-SET` к VPN-группе и настройте `MATCH` на `DIRECT`. Имя группы и полная конфигурация зависят от вашего клиента. Доменные правила этих клиентов используют суффикс и могут работать иначе, чем IP-маршруты Amnezia.

Прежний список российских сайтов для противоположного режима сохранён в `dist/tunneling-list.json` и `dist/catalog.json`. Не импортируйте его в режим «сайты из списка должны открываться через VPN»: тогда российские сайты пойдут через VPN.

## Обновление

GitHub Actions запускает **Update VPN-only lists** каждый час, после изменения исходных файлов и вручную через **Run workflow**. Сборка использует DNS-over-HTTPS и официальный список Telegram; сетевые ошибки или подозрительно короткий список сетей останавливают запись новых файлов. GitHub может задержать запуск. Импорт в Amnezia автоматически не обновляется: скачайте новый файл и повторите импорт.

Локально нужен 64-битный PHP 8.2+ с `curl` и доступ к `dns.google`, `cloudflare-dns.com`, `dns.adguard-dns.com`, `core.telegram.org`:

```sh
php tests/vpn.php
php bin/build-vpn.php
php tests/vpn-artifacts.php
```

Список доменов и категории редактируются в `sources/vpn-services.json`. Отчёт `vpn-report.json` указывает домены, не получившие IPv4. Веб-страница читает обновлённый каталог из публичной ветки репозитория.
