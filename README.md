# RU Routing PHP

PHP-сборщик правил раздельного туннелирования: выбранные российские сервисы открываются **напрямую**, остальной трафик идёт через ваш VPN. Самостоятельная PHP-реализация с расширенным каталогом доменов, сверенным с [amnezia-vpn-russia](https://github.com/kozlovartem20201/amnezia-vpn-russia). Источники и принципы отбора описаны в [SOURCES.md](SOURCES.md).

В каталоге **826 уникальных доменов** по 11 категориям: банки и страхование; госуслуги; магазины и доставка; технологии и соцсети; медиа; транспорт; связь; образование; медицина; недвижимость, авто и работа; крупные компании. Количество доменов, прошедших DNS-проверку, и количество сетей в текущей сборке смотрите в [dist/report.json](dist/report.json).

Это генератор правил, а не VPN-сервер или PHP-прокси. Для маршрутизации нужен клиент Amnezia VPN, sing-box либо Clash/Mihomo.

## Быстрый старт для Amnezia

1. Откройте [dist/tunneling-list.json](dist/tunneling-list.json), нажмите **Raw**, сохраните файл с расширением `.json`.
2. Отключите VPN. Откройте настройки раздельного туннелирования **сайтов**.
3. Выберите режим **«Адреса из списка не должны открываться через VPN»**.
4. Импортируйте JSON. «Заменить список» удалит ваши прежние исключения; сохраните их заранее или используйте добавление к существующим.
5. Подключитесь и проверьте IP на `yandex.ru/internet` и `ifconfig.me`: ожидаются IP провайдера и VPN соответственно. Это проверка двух адресов, а не всех сервисов.

Схема JSON содержит `hostname`, первый IPv4 в `ip` и все найденные IPv4 в `ips` для разных версий Amnezia. Реальный импорт и маршрутизация зависят от версии клиента и протокола; проверяйте на своём устройстве. Для AmneziaWG/WireGuard используйте профиль полного туннеля, совместимый с раздельным туннелированием клиента. Сборщик не меняет `AllowedIPs` и сетевые настройки ОС.

## Сборка

Требуется **64-битный PHP 8.2+**, расширение `curl`, системные CA-сертификаты и HTTPS-доступ к `dns.google`, `cloudflare-dns.com`, `www.ipdeny.com`, `stat.ripe.net`. Composer не нужен.

```bash
# Debian / Ubuntu
sudo apt install php-cli php-curl ca-certificates
php tests/run.php
php bin/build.php
```

В обычном режиме в IP-правила попадают:

- IPv4 выбранных доменов и их `www` из RU-списка IPdeny;
- подсети выбранных сервисов из `sources/asn.txt`, обновляемые по BGP-анонсам RIPEstat и **обрезанные по пересечению с RU-списком**;
- только конкретные адреса выбранных доменов в сетях из `sources/protection-asn.txt` — даже при регистрации сети вне RU;
- ваши явно заданные CIDR.

Cloudflare, AWS, Akamai и другие зарубежные CDN целиком не исключаются. Причины пропуска доменов, отфильтрованные IP, ошибки DNS и статистика по каждому ASN доступны в `dist/report.json`. При временной ошибке Google DNS запрос повторяется через Cloudflare DNS. Нормальный ответ NXDOMAIN не считается сетевой ошибкой.

```bash
# Необязательный широкий режим: все IPv4-подсети из RU-списка
php bin/build.php --all-ru
```

`--all-ru` отправит напрямую значительно больше трафика, включая сайты вне исходного списка. Стандартное расписание собирает узкий режим; чтобы постоянно использовать широкий, измените команду в workflow.

## Свои сервисы

- `sources/domains.txt`: домены без схемы, порта, пути и `*`. Кириллица — в punycode. Комментарии начинаются с `#`.
- Поддомены для входа, API, статики добавляйте **отдельно**: IP корневого домена не покрывает автоматически его поддомены. Вариант `www` проверяется автоматически; его разрешённые IPv4 объединяются с адресами исходного домена.
- `sources/cidr.txt`: доверенные публичные IPv4-подсети в CIDR. Они исключаются целиком, даже при регистрации вне RU. Частные, служебные и маршрут по умолчанию запрещены.
- `sources/asn.txt`: ASN самих сервисов. Не добавляйте целиком ASN облачных платформ и интернет-провайдеров. Полные сети из этого файла обновляются по RIPEstat и пересекаются с RU.
- `sources/protection-asn.txt`: дополнительные ASN для точечного допуска адресов выбранных доменов. Полные сети из этого файла **не попадают** в результат. На одном разрешённом IP всё равно могут жить посторонние сайты.

Для банковских мобильных приложений могут требоваться отдельные исключения приложений в VPN-клиенте. Список не гарантирует покрытие всех внутренних API сервисов.

## Выходные файлы

| Файл в `dist/` | Назначение |
| --- | --- |
| `tunneling-list.json` | Импорт исключений сайтов Amnezia |
| `ru-subnets.txt` | IPv4/CIDR сервисов и отдельные адреса доменов; не все сети РФ |
| `domains.txt` | Домены, у которых нашёлся хотя бы один разрешённый IPv4 |
| `sing-box.json` | Source rule-set v3 для sing-box 1.11+ |
| `clash.yaml` | Classical rule-provider для Clash/Mihomo |
| `report.json` | Дата сборки, режим, количество правил, пропущенные домены |

### sing-box

Разместите `dist/sing-box.json` рядом с конфигурацией sing-box. Объедините этот фрагмент с существующей конфигурацией, до общих правил VPN:

```json
{
  "route": {
    "rule_set": [
      { "tag": "ru-services", "type": "local", "format": "source", "path": "./sing-box.json" }
    ],
    "rules": [
      { "rule_set": "ru-services", "action": "route", "outbound": "direct" }
    ]
  }
}
```

В вашей конфигурации должен существовать outbound `direct`, а маршрут по умолчанию должен вести в VPN. Это фрагмент, не полный конфиг клиента. Для удалённого rule-set используйте raw-ссылку на файл в своём репозитории и `type: remote`, `url`, `update_interval: 1d` вместо `type: local`, `path`.

### Clash / Mihomo

```yaml
rule-providers:
  ru-services:
    type: file
    behavior: classical
    path: ./ru-services.yaml
rules:
  - RULE-SET,ru-services,DIRECT
  # Затем ваши остальные правила и MATCH на существующую VPN-группу
```

Скопируйте `dist/clash.yaml` в `ru-services.yaml` рядом с конфигом. Для HTTP-подписки используйте `type: http`, raw URL файла в поле `url` и `interval: 86400`.

**Доменная маршрутизация sing-box/Clash отличается от IP-списка Amnezia:** `domain_suffix` / `DOMAIN-SUFFIX` охватывает поддомены и может направить выбранный сервис напрямую даже при его переезде на зарубежный CDN. Настройка DNS и определения доменов выполняется в клиенте. Если нужны строго IP-исключения, используйте только `ru-subnets.txt` в настройках своего клиента.

## GitHub и автообновление

Код и готовые файлы можно хранить в обычном GitHub-репозитории. **GitHub Pages не исполняет PHP**: сборщик работает локально или в GitHub Actions, пользователи скачивают готовый JSON через Raw.

1. Создайте репозиторий с веткой `main`, загрузите содержимое проекта в корень.
2. Включите Actions, если GitHub попросит. Workflow **Update routing lists** запускается каждый час, ежедневно, на 23-й минуте часа, после изменения исходников и вручную через **Run workflow**. GitHub может задержать запуск.
3. Workflow выполняет тесты, сборку и сохраняет обновлённый `dist/`. Для бота нужны права записи Contents; workflow запрашивает их. Если политика организации или защита `main` запрещает прямой push, потребуется адаптировать публикацию под PR.
4. Проверяйте `dist/report.json`. Amnezia после обновления репозитория требует повторного ручного импорта.

Автоматика обновляет IP существующих доменов и BGP-подсети выбранных ASN. Новые сервисы добавляются в исходный каталог вручную: содержимое стороннего репозитория автоматически не исполняется и не импортируется.

Недоступность списка RU или RIPEstat после повторов, некорректные подсети, массовые ошибки DNS, отсутствие разрешённых IP у более половины доменов и падение числа принятых доменов или подсетей сервисов более чем на 30% относительно предыдущего отчёта останавливают сборку до записи результатов. Если каталог сознательно сокращён, после проверки причин уберите старый `dist/report.json` перед локальной сборкой, затем загрузите все новые файлы одним коммитом.

Каждый файл заменяется через rename из временной папки; вся папка не является единой транзакцией, поэтому не запускайте потребителей во время локальной публикации. На GitHub файлы публикуются одним коммитом. Параллельные локальные сборки блокируются lock-файлом.

## Ограничения

- RU в базе регистрации не доказывает физическое местоположение IP или исключительное владение им. Общий хостинг/CDN может отправить напрямую посторонние сайты с тем же адресом. Список не определяет блокировки сайтов в РФ.
- IP сервисов меняются, результат Google DNS может отличаться от DNS вашего провайдера. Поддомены, балансировка, AAAA и мобильные API требуют отдельной проверки. Автоматическая сборка — снимок, не гарантия доступности.
- Генерируются только IPv4-правила. Поведение IPv6 задаёт клиент; эти файлы его не настраивают.
- Сервисы, исключённые из VPN, видят IP прямого подключения. Если вы за пределами России, это будет IP вашей текущей страны: список сам по себе не даёт российский IP.
- Запросы списка доменов при сборке отправляются Google DNS-over-HTTPS, при ошибке — Cloudflare DNS-over-HTTPS. CIDR-данные берутся у [IPdeny](https://www.ipdeny.com/ipblocks/) и [RIPEstat](https://stat.ripe.net/), условия их использования определяют поставщики.

## Категории и страница

В `dist/catalog.json` собраны категории и адреса выбранных доменов. Файлы `category-<название>-amnezia.json`, `-sing-box.json`, `-clash.yaml` и `-cidr.txt` формируются для каждой категории при каждой сборке. Категории содержат только точечные IPv4 доменов: сети компаний целиком находятся в общем файле. Это уменьшает охват адресов при балансировке; сверяйте результат со своим клиентом.

Страница `site/index.html` позволяет выбрать несколько категорий и скачать файл для Amnezia, sing-box, Clash/Mihomo или список IPv4. Для просмотра локально выполните из корня `php -S 127.0.0.1:8000` и откройте `http://127.0.0.1:8000/site/`. Страница читает `dist/catalog.json`; при отдельном размещении сайта необходимо разместить каталог по тому же относительному пути. Файл в приватном репозитории недоступен анонимным посетителям. Для свежих адресов можно загрузить в страницу текущий `dist/tunneling-list.json` вручную.

В `dist/report.json` раздел `changes` содержит добавленные и пропавшие домены, изменения IPv4 по сравнению с предыдущей сборкой. `skip_reasons`, `dns_errors` и `filtered_addresses` объясняют пропуски. Результаты DNS зависят от географии и CDN и могут меняться между запусками.

Workflow **Discover new service domains** раз в день сверяет текущий список с каталогом проекта-источника и проверяет наличие IPv4 из RU IPdeny. Новые кандидаты предлагаются в PR в файле `CANDIDATES.md`; в маршруты они автоматически не добавляются. Принадлежность и доступность сервисов необходимо проверить вручную, затем перенести подходящие домены в соответствующие разделы `sources/domains.txt`. Для PR в настройках репозитория Actions должна быть разрешена опция создания pull request. Ошибки расписания или разрешений видны во вкладке Actions.

Для пошаговой настройки форматов и ограничений разных клиентов см. [CLIENTS.md](CLIENTS.md).
