# RU Routing PHP

PHP-сборщик правил раздельного туннелирования: выбранные российские сервисы открываются **напрямую**, остальной трафик идёт через ваш VPN. Вдохновлён [amnezia-vpn-russia](https://github.com/kozlovartem20201/amnezia-vpn-russia), реализация и начальный список написаны отдельно.

Это генератор правил, а не VPN-сервер или PHP-прокси. Для маршрутизации нужен клиент Amnezia VPN, sing-box либо Clash/Mihomo.

## Быстрый старт для Amnezia

1. Откройте [dist/tunneling-list.json](dist/tunneling-list.json), нажмите **Raw**, сохраните файл с расширением `.json`.
2. Отключите VPN. Откройте настройки раздельного туннелирования **сайтов**.
3. Выберите режим **«Адреса из списка не должны открываться через VPN»**.
4. Импортируйте JSON. «Заменить список» удалит ваши прежние исключения; сохраните их заранее или используйте добавление к существующим.
5. Подключитесь и проверьте IP на `yandex.ru/internet` и `ifconfig.me`: ожидаются IP провайдера и VPN соответственно. Это проверка двух адресов, а не всех сервисов.

Схема JSON содержит `hostname`, первый IPv4 в `ip` и все найденные IPv4 в `ips` для разных версий Amnezia. Реальный импорт и маршрутизация зависят от версии клиента и протокола; проверяйте на своём устройстве. Для AmneziaWG/WireGuard используйте профиль полного туннеля, совместимый с раздельным туннелированием клиента. Сборщик не меняет `AllowedIPs` и сетевые настройки ОС.

## Сборка

Требуется **64-битный PHP 8.2+**, расширение `curl`, системные CA-сертификаты и HTTPS-доступ к `dns.google`, `www.ipdeny.com`. Composer не нужен.

```bash
# Debian / Ubuntu
sudo apt install php-cli php-curl ca-certificates
php tests/run.php
php bin/build.php
```

По умолчанию в IP-правила попадают **только IPv4 выбранных доменов**, находящиеся в RU-списке IPdeny, плюс ваши явно заданные CIDR. Домены с иностранными IP пропускаются. Если у домена одновременно RU и зарубежные IP, в Amnezia попадут только RU-адреса. Не разрешённые записи видны в `dist/report.json`.

```bash
# Необязательный широкий режим: все IPv4-подсети из RU-списка
php bin/build.php --all-ru
```

`--all-ru` отправит напрямую значительно больше трафика, включая сайты вне исходного списка. Стандартное расписание собирает узкий режим; чтобы постоянно использовать широкий, измените команду в workflow.

## Свои сервисы

- `sources/domains.txt`: домены без схемы, порта, пути и `*`. Кириллица — в punycode. Комментарии начинаются с `#`.
- Поддомены для входа, API, статики добавляйте **отдельно**: IP корневого домена не покрывает автоматически его поддомены. `www` автоматически не добавляется.
- `sources/cidr.txt`: доверенные публичные IPv4-подсети в CIDR. Они исключаются целиком, даже при регистрации вне RU. Частные, служебные и маршрут по умолчанию запрещены.

Для банковских мобильных приложений могут требоваться отдельные исключения приложений в VPN-клиенте. Список не гарантирует покрытие всех внутренних API сервисов.

## Выходные файлы

| Файл в `dist/` | Назначение |
| --- | --- |
| `tunneling-list.json` | Импорт исключений сайтов Amnezia |
| `ru-subnets.txt` | IPv4/CIDR: в обычном режиме IP сервисов, а не все сети РФ |
| `domains.txt` | Домены, у которых нашёлся хотя бы один разрешённый IPv4 |
| `sing-box.json` | Source rule-set v3 для sing-box 1.11+ |
| `clash.yaml` | Classical rule-provider для Clash/Mihomo |
| `report.json` | Дата сборки, режим, количество правил, пропущенные домены |

### sing-box

Разместите `dist/sing-box.json` рядом с конфигурацией sing-box. Объедините этот фрагмент с существующей конфигурацией, до общих правил VPN:

```json
{
  "route": {
    "rule_set": [
      { "tag": "ru-services", "type": "local", "format": "source", "path": "./sing-box.json" }
    ],
    "rules": [
      { "rule_set": "ru-services", "action": "route", "outbound": "direct" }
    ]
  }
}
```

В вашей конфигурации должен существовать outbound `direct`, а маршрут по умолчанию должен вести в VPN. Это фрагмент, не полный конфиг клиента. Для удалённого rule-set используйте raw-ссылку на файл в своём репозитории и `type: remote`, `url`, `update_interval: 1d` вместо `type: local`, `path`.

### Clash / Mihomo

```yaml
rule-providers:
  ru-services:
    type: file
    behavior: classical
    path: ./ru-services.yaml
rules:
  - RULE-SET,ru-services,DIRECT
  # Затем ваши остальные правила и MATCH на существующую VPN-группу
```

Скопируйте `dist/clash.yaml` в `ru-services.yaml` рядом с конфигом. Для HTTP-подписки используйте `type: http`, raw URL файла в поле `url` и `interval: 86400`.

**Доменная маршрутизация sing-box/Clash отличается от IP-списка Amnezia:** `domain_suffix` / `DOMAIN-SUFFIX` охватывает поддомены и может направить выбранный сервис напрямую даже при его переезде на зарубежный CDN. Настройка DNS и определения доменов выполняется в клиенте. Если нужны строго IP-исключения, используйте только `ru-subnets.txt` в настройках своего клиента.

## GitHub и автообновление

Код и готовые файлы можно хранить в обычном GitHub-репозитории. **GitHub Pages не исполняет PHP**: сборщик работает локально или в GitHub Actions, пользователи скачивают готовый JSON через Raw.

1. Создайте репозиторий с веткой `main`, загрузите содержимое проекта в корень.
2. Включите Actions, если GitHub попросит. Workflow **Update routing lists** запускается по понедельникам, после изменения исходников и вручную через **Run workflow**.
3. Workflow выполняет тесты, сборку и сохраняет обновлённый `dist/`. Для бота нужны права записи Contents; workflow запрашивает их. Если политика организации или защита `main` запрещает прямой push, потребуется адаптировать публикацию под PR.
4. Проверяйте `dist/report.json`. Amnezia после обновления репозитория требует повторного ручного импорта.

Сетевые ошибки, некорректные подсети и потеря разрешённых IP у более половины доменов останавливают сборку до записи результатов. Каждый файл заменяется через rename из временной папки; вся папка не является единой транзакцией, поэтому не запускайте потребителей во время локальной публикации. На GitHub файлы публикуются одним коммитом. Параллельные локальные сборки блокируются lock-файлом.

## Ограничения

- RU в базе регистрации не доказывает физическое местоположение IP или исключительное владение им. Общий хостинг/CDN может отправить напрямую посторонние сайты с тем же адресом. Список не определяет блокировки сайтов в РФ.
- IP сервисов меняются, результат Google DNS может отличаться от DNS вашего провайдера. Поддомены, балансировка, AAAA и мобильные API требуют отдельной проверки. Автоматическая сборка — снимок, не гарантия доступности.
- Генерируются только IPv4-правила. Поведение IPv6 задаёт клиент; эти файлы его не настраивают.
- Сервисы, исключённые из VPN, видят IP прямого подключения. Если вы за пределами России, это будет IP вашей текущей страны: список сам по себе не даёт российский IP.
- Запросы списка доменов при сборке отправляются Google DNS-over-HTTPS. CIDR-данные берутся у [IPdeny](https://www.ipdeny.com/ipblocks/), условия их использования определяет поставщик.
